## B1 — 系统级全局热键注册

**状态: ✅ 完全一致**

### 决策要求
1. 使用 Windows API `RegisterHotKey` + `QAbstractNativeEventFilter`
2. 零额外依赖（仅 ctypes + Qt）
3. 不与窗口焦点绑定，任何应用下均可触发

### 代码证据

**hotkey.py:42-83** — `HotkeyManager` 类
- 使用 `ctypes.windll.user32.RegisterHotKey(target_hwnd, ...)` 注册全局热键
- 结合 `QObject` 继承，无额外运行时依赖
- `register()` 接受 `target_hwnd` 参数，热键绑定到窗口 HWND 而非线程队列
- 使用 `MOD_NOREPEAT`（0x4000）防重复触发（`hotkey.py:60` `_modifiers_to_flags()`）

**hotkey.py:7-11** — 模块文档字符串
- 明确声明"使用 Windows API RegisterHotKey"
- 明确声明"WM_HOTKEY 的处理交由 WallpaperWindow.nativeEvent() 完成"

**window.py:788-813** — `WallpaperWindow.nativeEvent()`
- 拦截 `WM_HOTKEY`（0x0312），直接调用 `self.bring_to_front_and_edit()`
- 拦截 `WM_NCHITTEST`（0x84），统一返回 `HTCLIENT`（解决 WA_TranslucentBackground 下透明像素穿透点击的问题）
- 使用了 `QWidget.nativeEvent()` 而非全局 `QAbstractNativeEventFilter`——但两者语义等价，且注册在具体窗口 HWND 上时 per-widget 的 `nativeEvent()` 是更精准的方案

**app.py:101-102** — 启动时注册
```python
self._hotkey.register(target_hwnd=int(self._window.winId()))
```
热键注册放在 `window.show()` 之后，确保 HWND 稳定（符合架构设计中对 B2 的提及）

**tray.py** — 托盘菜单中"编辑"按钮也直接调用 `self._window.bring_to_front_and_edit()`

### 说明
- `QWidget.nativeEvent()` 是比 `QAbstractNativeEventFilter` 更自然的实现方式：注册在窗口 HWND 上的消息直接在窗口过程内拦截，不需要再经过全局过滤器分发。功能完全等价。
- 零额外依赖：仅 `ctypes`（标准库）+ `PySide6.QtCore.QObject` ✅

## B2 — 快捷键触发联动：置顶+编辑+聚焦

**状态: ✅ 完全一致**

### 决策要求
快捷键触发时，窗口必须**同时**完成：
1. HWND_TOPMOST 置顶
2. QStackedWidget 切换到编辑模式

用户看到窗口时已可直接打字。

### 代码证据

**window.py:421-502** — `bring_to_front_and_edit()` 完整方法

| 动作 | 代码位置 | 实现方式 |
|------|----------|----------|
| 窗口恢复（若最小化） | L444-447 | `IsIconic()` → `ShowWindow(SW_RESTORE)` |
| 移除 WS_EX_NOACTIVATE | L453-455 | `GetWindowLongW` + `SetWindowLongW` 清除标志 |
| **HWND_TOPMOST 置顶** | L458-461 | `SetWindowPos(hwnd, HWND_TOPMOST, ..., SWP_SHOWWINDOW)` |
| SwitchToThisWindow | L467 | 模拟 Alt+Tab 切换（核心方案） |
| SetForegroundWindow | L470+ | 多层防御：Alt keybd_event → AttachThreadInput → BringWindowToTop |
| Qt 同步 | L493-495 | `activateWindow()` + `raise_()` |
| **QStackedWidget 切编辑模式** | L498 | `self._switch_edit()` |
| **QPlainTextEdit 获取焦点** | L498内 `_switch_edit()` 实现 | `editor.setFocus()` + 从文件重载内容 |
| **延迟取消置顶** | L501 | `QTimer.singleShot(500, self._restore_zorder)` — 仅取消 TOPMOST，不影响已完成的状态 |

**window.py:834-853** — `_switch_edit()` 详细动作：
```python
stack.setCurrentIndex(1)           # ✅ 切换编辑模式
```

### 说明

- 500ms 后 `_restore_zorder()` 取消 TOPMOST 让窗口回到正常 Z 序——这与"置顶+编辑+聚焦"的瞬时动作无关

2. 修改后立即生效（`hotkey.rebind()`）

### 代码证据

#### ✅ 设置界面（settings.py）

- 四枚 CheckBox：Ctrl / Shift / Alt / Win ✅
- ComboBox 主键选择：A-Z, 0-9, F1-F12, Space, Tab 等 ✅
- 加开机自启 CheckBox ✅

#### ✅ rebind() 调用（app.py）
```python
# app.py:159-163 — OK 确认后执行
self._hotkey.rebind(new_mods, new_key, target_hwnd=int(self._window.winId()))
```
`hotkey.py:100-109` — `rebind()` 实现：
```python
def rebind(self, modifiers: list[str], key: str, target_hwnd: int) -> bool:
    was_registered = self._registered
    if self._registered:
        self.unregister()
    self._mod_flags = _modifiers_to_flags(modifiers)
    self._vk = _key_to_vk(key)
    if was_registered and target_hwnd:
        return self.register(target_hwnd)
    return True
```
✅ 先注销旧热键 → 更新参数 → 注册新热键

#### ✅ 持久化到 config.json（app.py）
```python
# app.py:157-159
config_dict["hotkey"]["modifiers"] = new_mods
config_dict["hotkey"]["key"] = new_key
self._config.save_config(config_dict)
```
✅ 通过 `Config.save_config()` 写入 `config.json`

#### ⚠️ 默认值不一致

| 来源 | 值 |
|------|-----|
| **决策树 B3 statement** | `Ctrl+Shift+A` |
| **config.py:81** 代码 fallback 默认值 | `["ctrl", "shift"]` + `"n"` = **Ctrl+Shift+N** |
| **config.json**（实际操作配置文件） | `["ctrl", "alt"]` + `"a"` = **Ctrl+Alt+A** |

**三个不同的值，存在事实偏差。** 决策树与代码对默认值的认知不一致。

#### ⚠️ rebind() 边界处理（hotkey.py:100-109）

`rebind()` 的 `target_hwnd` 参数类型标注 `int`，但不为 0 提供错误处理：
- 若 `was_registered=True` 但 `target_hwnd` 为 0/falsy → 旧热键已注销，新热键未注册，函数静默返回 `True`
- 代码中调用方 `app.py:163` 始终传入有效的 `int(self._window.winId())`，实际不会触发此路径
- 属于代码层面的轻微鲁棒性问题，不影响当前行为

#### ⚠️ Apply 按钮与快捷键

`settings.py:363` — Apply 按钮逻辑：
```python
def _on_apply(self) -> None:
    _, _, theme, _ = self.get_result()  # 丢弃 modifiers, key, autostart
    self.applied.emit(theme)
```
Apply 按钮仅预览**主题**变更，**不触发热键 rebind**。热键 rebind 仅在对话框 OK 确认后触发。决策树 C16_1 陈述"修改后调用 hotkey.rebind() 即时生效"——OK 确认后确实立即生效，与"不关闭对话框预览"的 Apply 设计不矛盾。

| **C16_1** 快捷键设置面板 | ✅ | 控件类型、rebind 调用、持久化全部一致 |

### 发现的总偏差

1. **默认快捷键值不一致**（严重度：中）
   - 决策树 B3 statement："默认值为 Ctrl+Shift+A"
   - `config.py:81` fallback：`["ctrl", "shift"]` + `"n"`（Ctrl+Shift+N）
   - `config.json`：`["ctrl", "alt"]` + `"a"`（Ctrl+Alt+A）
   - **建议**：统一决策树文档或代码默认值。如果决策树是权威来源，应将 `config.py` 的 fallback 改为 `"a"`；如果代码已投产且 config.json 是正确的，应更新决策树。

2. **`rebind()` 边界处理不完整**（严重度：低）
   - `hotkey.py:108`：当 `target_hwnd` 为 0 时丢失新热键注册且静默返回 `True`
   - 当前调用方无此问题，但方法签名未做防御

3. **Apply 按钮不触发热键 rebind**（严重度：低，属于设计选择）
   - Apply 只预览主题效果，热键变更需 OK 确认
   - 决策树中 C16_1、"修改后立即生效"在 OK 确认后确实立即生效，与 Apply 隔离的设计不矛盾

### 额外观察（代码中的决策亮点）

- `bring_to_front_and_edit()` 中**多层防御策略**（第 1-7 步）：窗口恢复 → 清除 WS_EX_NOACTIVATE → TOPMOST → SwitchToThisWindow → SetForegroundWindow 带 keybd_event/AttachThreadInput 后备 → BringWindowToTop → Qt 同步。这种防御性设计在决策树中未曾提及，是实际开发中值得记录的实践经验。
- `nativeEvent()` 同时处理 `WM_NCHITTEST` 解决 WA_TranslucentBackground 下的点击穿透问题，是 B1 实现中未在决策树中记录的关键补充。
- 热键默认值从建立到代码存在**三次变化**的证据（决策树→代码 fallback→实际 config.json），可能反映了开发过程中的迭代，但未同步更新决策树。
